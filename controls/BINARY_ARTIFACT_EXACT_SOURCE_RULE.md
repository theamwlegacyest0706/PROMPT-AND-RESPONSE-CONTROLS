# Binary artifact exact-source rule

For every Legacy image, PDF, document, spreadsheet, archive, video, or other binary artifact, the GitHub memory layer must preserve the exact Library source identity available to it: file_id, library_file_id, path/name, creation/modification metadata, model-generated status when available, authority/status metadata, and lineage pointers.

An inventory reference is not permission to recreate or approximate the artifact. Before visual editing, approval claims, recovery conclusions, or exact-artifact comparison, retrieve the exact source artifact from the Library/verified durable source and run the actual artifact through the applicable controls, Mirror Review, Python validation, and GitHub validation.

Rejected, superseded, draft, historical, quarantined, recovery-gap, source-evidence, Founder-approved, Update-and-Saved, and Current-Controlled artifacts remain preserved as distinct states. Status governs authority, never preservation.
